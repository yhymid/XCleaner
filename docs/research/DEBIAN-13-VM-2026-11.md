# Debian 13 (Xfce) in a VM: field data (2026-11-23)

**English** | [Polski](DEBIAN-13-VM-2026-11.pl.md)

One-time data collection on Debian 13.8 "trixie" installed from the official Xfce live image
(QEMU/KVM, 4 vCPU, 4 GiB RAM, 20 GiB disk), with the `.deb` built from commit `c5a5f01`.
Raw outputs (65 files + scenario + cleaning history) stay on the owner's machine
(`~/vm/data-debian13/`). Root-only areas were read with a temporary passwordless sudo rule,
removed afterwards. See also [FEDORA-45-VM-2026-11.md](FEDORA-45-VM-2026-11.md).

## 2. XCleaner results

- `.deb` (built on ubuntu:24.04) installs with `apt install ./…deb`, adds menu entry and icon.
- `--scan`: 3.6–4.3 s (Fedora: 2.0 s), EN and PL identical apart from number format.
- GUI on Xfce/X11: no warnings at start (Fedora had Mesa/ZINK warnings). libadwaita
  renders with its own style; EN ⇄ PL switch works (owner screenshots).
- **Leftover detection works on Debian.** After `apt-get install mc ranger htop`, running
  `ranger` and `apt-get remove`, XCleaner listed `~/.config/ranger` as *certain*: "package
  ranger was removed …; the directory appeared 4 s after the package was installed".
  Evidence comes from `/var/log/dpkg.log` (0644, readable by the user). `~/.config/htop`
  was not offered: `htop` is on the shared-names list (expected).
- **Root tasks via the terminal work:** the journal shows
  `sudo … COMMAND=/usr/bin/env APPIMAGELAUNCHER_DISABLE=1 /usr/bin/xcleaner --root-clean --uid 1000 --report /run/user/1000/xcleaner-root-1551.txt apt-clean rotated-logs`
  on `TTY=pts/0`, i.e. inside a terminal window. Result: `root:apt-clean` 3.9 MiB and
  `root:rotated-logs` 64 KiB, 0 errors.

## 3. Bugs found

1. **ibus socket deleted (serious).** `~/.config/ibus/bus/<machine-id>-unix-0` contains
   `IBUS_ADDRESS=unix:path=/home/debian/.cache/ibus/dbus-Rw4vdaUd`; `ss -xlp` shows
   `ibus-daemon` listening on that path. Cleaning `cache:ibus` removed the socket file while
   the daemon ran, and the window log then printed
   `IBUS-WARNING: Unable to connect to ibus`. Every program started afterwards has no input
   method until the next login. Fixes: never delete sockets, FIFOs or device files during
   cleaning (`fsops.rs` has no check for them today), and do not offer `~/.cache/ibus` while
   `ibus-daemon` runs.
2. **Mesa shader cache race.** 5 × `.cache/mesa_shader_cache_db/partNN: Directory not empty
   (os error 39)`: GL programs (XCleaner's own GTK renderer included) write new parts while
   the directory is being removed. The second run freed only 68 KiB. Treat ENOTEMPTY on a
   cache that is being rewritten as "skipped, in use", not as an error, or skip it while GL
   programs run.
3. **Dates in UTC.** `leftovers::format_date` formats in UTC. The package was removed on
   2026-11-22 20:33 local time (EST) and the row says "removed 2026-11-23". In CET the same
   happens for removals between 23:00 and 01:00. Use the local date.
4. **Empty-state icon.** On Xfce's icon theme the "All clean" page shows a large red ✗ on a
   drive icon, which reads as an error. Ship our own icon or use a check mark.

## 6. Limits

- One fresh install from the live image; real systems have more cache, logs and kernels.
- The GUI was started over SSH with a reduced environment (`XDG_SESSION_TYPE=tty`, no
  `XDG_CURRENT_DESKTOP`), so the "session" line in the events window is empty and the
  terminal was chosen by the fallback order, not by desktop detection. Which terminal
  opened was not recorded; the journal only proves a pseudo-terminal (`pts/0`).
- Scan time difference was not profiled.
